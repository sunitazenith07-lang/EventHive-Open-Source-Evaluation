# Evaluation workflow

Fork this repository, create a focused branch, inspect the existing implementation, run `python -m pytest -q`, and open one pull request to the original repository. Do not merge it.

## Mandatory assessed documentation
Complete these three Markdown files from the templates in the repository:
1. `approach.md` — approach, investigation evidence, experiments, and implementation strategy.
2. `challenges.md` — **compulsory**; actual challenges, what you tried, evidence, resolution, and remaining limitations. If none arose, say so honestly and describe the hardest edge case you tested.
3. `optimizations.md` — optimizations considered or implemented, trade-offs, measured effects if measured, and future improvements.

All three files are required and together are worth 15 marks (5 marks each). Empty, generic, copied, or unsupported claims receive no marks for the relevant part. Document the real engineering process and rationale, not a private hidden chain-of-thought transcript.

Complete `TESTING.md` and `ORDER_FLOW_NOTES.md` too, as required by the problem statement. Link or mention the documentation in your pull request.

AI chatbots, generated code, AI completion and solution-sharing are prohibited for this evaluation. Standard non-AI documentation is allowed. Do not submit code you cannot explain; a short live modification may be requested.
